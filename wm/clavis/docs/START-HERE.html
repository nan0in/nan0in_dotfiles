niri + Clavis：安装、定制与日常使用

1. 桌面的组成

  • niri：窗口、工作区、显示器、快捷键、截图与焦点。
  • Clavis：状态栏、Dock、搜索、通知、快捷设置、中间拱石、壁纸与设置中心。
  • Ambxst / Hyprland：保留的旧桌面；不与 Clavis 同时启动。
  • Quickshell / Qt：Clavis 的运行框架。Clavis 不是另一个 niri 二进制或登录 session。

普通登录界面选择 Niri 就使用这套配置，无自定义启动命令。 目录现在统一为 wm/clavis/、wm/ambxst/，原个人 Hyprland/Ambxst 配置仍在 config 包中。

2. 安装与更新（仓库根目录执行）

./scripts/setup-clavis.sh check
./scripts/setup-clavis.sh deps
./scripts/setup-clavis.sh appearance  # Dracula；保留字体、图标和旧 Kvantum
./scripts/setup-clavis.sh build
./scripts/setup-clavis.sh install
niri validate -c ~/.config/niri-clavis/config.kdl

deps 下载、验签并安装私有依赖到 ~/.local/opt/nan0in-clavis-deps/，不替换系统 Qt。 Qt 升级后需重新构建。源码来源、固定提交与许可证在 wm/clavis/UPSTREAM 和源码目录中。 这是本地源码分支，不代表已创建 GitHub 远端 fork。

install 只管理已登记的文件和链接：

  • 源码链接稳定为 ~/.local/src/clavis/ 和 ~/.config/quickshell/clavis/。
  • niri 配置首次复制到真实目录 ~/.config/niri-clavis/，解决上游拒绝写入软链接路径的问题。
  • 后续只更新内容仍等于上次安装哈希的管理文件；发现手改就打印 PRESERVE。
  • local.kdl、clavis/*.kdl、settings/* 已存在就保留。local.kdl 是推荐个人覆盖入口。
  • 存在不属于本安装的路径则先停止，不采用 stow --adopt 或强制覆盖。
  • 安装器不重启桌面。需要刷新界面：systemctl --user restart clavis-shell.service。
  • 当前原始 ~/.config/niri/ 完整保留；原截图、scratch 等脚本仍从这里调用；Clavis 锁屏使用独立入口，旧锁屏脚本保留。

Ambxst 的旧包名继续有效：./install.sh stow ambxst；实际使用 wm/ 作为 Stow 包根。 不要对整个 wm/ 运行 Stow，也不要对整个 Clavis 包盲目 Stow。

3. 先找到状态栏和设置

入口 动作
Super+Ctrl+B 直接进入状态栏设置，开启“显示栏”、选择上下左右与模块
Super+Shift+C 打开设置中心
Super+Space 搜索／启动应用；下次登录亦可轻按 Super 松开打开，组合键不触发
Super+Period Spotlight 内的 Emoji 搜索；选择后复制并关闭
Super+A 快捷设置侧栏
Super+D 打开／关闭 Dashboard 侧栏
Super+Ctrl+N 网络连接设置
Super+F1 读取当前有效配置的全部快捷键
Super+Alt+B 刷新 Clavis 和剪贴板服务，不重启 niri

状态栏、Dock、拱石是三个独立组件：

  • 栏：设置 → 常规 → 栏；模块可移除、添加、排序。
  • Dock：设置 → 常规 → Dock，显示应用、固定项目和文件夹；始终覆盖而不挤占应用空间，关闭自动隐藏也一样。
  • 拱石：设置 → Keystone／拱石，选择时钟、媒体与工具的布局和位置。

搜索位置可在 设置 → 通用 → Spotlight → 弹出位置 修改：

  • 跟随状态栏（默认）：底部栏向上展开，其他位置保留上方搜索布局。
  • 顶部 / 居中 / 底部：独立于状态栏位置；底部结果向上展开，顶部与居中向下展开。
  • 修改即时生效并保存，下次登录保留；应用、文件、剪贴板和计算器共用这个位置。

可直接打开该设置页：qs -c clavis ipc call control-center open general.spotlight。

单独轻按 Super 的原生实现已安装到私有 niri-edge，下次正常 Niri 登录生效。 松开时才触发，组合键、鼠标操作、长按与锁屏状态不触发；保留 Super+Space 备用。 设置页可填 Mod／Super，保存为 Super_L，绑定仍可修改／删除，不使用全局监听服务。 见 单独轻按 Super。

栏与拱石处在同一水平边时，左右模块会按可用空间收紧，为中间拱石预留空位。 通知／快捷设置仍是左右侧栏，不是向下弹出的应用菜单。

命令行救援入口：

systemctl --user start clavis-shell.service
qs -c clavis ipc call control-center open general.bar
journalctl --user -u clavis-shell.service -b -n 100 --no-pager

4. niri 的基本操作

niri 的平铺是横向滚动的“列”，不是 Hyprland 的 dwindle 二叉树。 窗口进列，列排列在工作区中；列可含多个窗口，并可切成标签式显示。

操作 键位
开终端 Super+Q / Super+Enter
关窗口 Super+W
列／窗口方向切换 Super+方向键
移动窗口／列 Super+Shift+方向键
切工作区 Super+1…9（其余键位见 F1）
把窗口送到指定工作区 Super+Shift+1…9
跨显示器聚焦 Super+Ctrl+方向键
窗口跨显示器 Super+Ctrl+Shift+方向键
列普通／标签显示切换 Super+J
锁屏 Super+L，使用设置中的 Clavis 样式，swaylock 兜底
工作区全部浮动／全部平铺 Super+Shift+F
浮动／平铺区域切换焦点 Super+Alt+F
列最大化 Super+M
文件管理器 Super+E，遵循默认应用设置
OCR / 区域录屏 Super+Shift+A / Super+Shift+R；录屏同键停止

工作区整体浮动再平铺不保证还原原列分组；J 也不是完整布局算法循环。 保留原 scratch 机制，但不会把普通最小化偷偷等同于移动到隐藏工作区。 快捷键现在统一在 Clavis 设置的快捷键页编辑／删除；不会被旧绑定恢复。 手动添加过 local.kdl 覆盖的键仍由该文件管理。

参考 全部有效快捷键 和 Ambxst 差异表。

5. 文件夹和默认应用

当前默认文件管理器是 Nautilus（文件）。Super+E、拱石工具及 Dock／Shell 的本地文件夹入口， 先由 GIO 按系统 inode/directory 默认关联打开，不再写死 Thunar。 默认处理器命令失败／缺失时才依次尝试 Nautilus → Thunar → Dolphin。

以后在 设置 → 常规 → 默认应用 → 文件管理器 选择；重开该页会读取当前系统值。 旧 ~/.config/niri-mimeapps.list 中强制 Dolphin 的目录项已单独移除，其他行保留， 因此设置页／xdg-mime 的修改不再被高优先级覆盖。Nautilus 自身的偏好设置没有被改动。 具体 GUI、命令、视图／隐藏文件配置与备份见 Nautilus 配置教程。

6. 托盘与最小化

设置 → 常规 → 栏 → 常驻托盘图标：开启的常驻外侧，其余放进折叠区。 也可鼠标中键点击托盘图标在两区之间切换。选择持久化在 settings/tray.json。 列表按应用实际注册的托盘 ID 展示；尚未启动、未注册托盘图标的程序不会出现。

“最小化到托盘”由应用自身实现，例如聊天／同步程序要在自己的设置里开启该选项。 应用自带托盘模式控制窗口何时隐藏，Clavis 控制其图标位置；另提供下述无托盘窗口折叠策略。 本机正常 Niri 登录现已使用私有 niri-edge，Dock 可原生最小化／恢复；保留发行版 niri， 不伪装成隐藏工作区，不创建自定义登录 session 或启动包装命令。安装与回退见 私有 compositor 说明。无托盘程序现可在“折叠最小化程序”中选择，详见文末操作说明。

7. 网络、连接与蓝牙

本机 NetworkManager、bluetooth 服务运行中，已经有网络管理界面，不需要再装另一套面板。

  • Super+Ctrl+N：Wi-Fi／已保存连接／有线连接相关设置；认证走保留的 polkit agent。
  • Super+A：网络、蓝牙、音频、亮度快捷开关；图标旁的详情进入连接列表。
  • 托盘 nm-applet：备用的 NetworkManager 图形入口。
  • nm-connection-editor：更完整的连接配置，适合静态 IP、DNS、VPN 等高级项目。
  • nmtui：无图形面板时的终端连接编辑工具。
  • 蓝牙可从快捷设置进入配对页面；已有 blueman 托盘也保留。

只读诊断：

nmcli general status
nmcli device status
nmcli connection show --active
systemctl is-active NetworkManager bluetooth

不在文档示例中保存 Wi-Fi 密码；VPN 需对应类型的 NetworkManager 插件。 官方说明：nmcli、 nmtui。 Clavis 云盘页需要额外 rclone；它不是网络连接服务，不会为解决联网问题自动安装或创建远端。

8. 字体与主题

顶部中文日期单独使用已安装的 Noto Sans CJK SC，缺字时回退 UI 字体；数字时钟仍用原 Google Sans Flex。 不改你选择的霞鹜文楷 UI／等宽字体。字体角色定义在源码 Common/Fonts.qml。

niri 保留 QT_QPA_PLATFORMTHEME=qt6ct；不再固定 GTK_THEME／QT_STYLE_OVERRIDE， 避免会话变量覆盖你在设置页的选择。

设置 → 主题 → 应用外观：GTK3 主题、应用图标、Qt6 控件样式／配色、Kvantum 主题均可选择， 显示当前方案描述。GTK3 已应用 Clavis Material Dracula，基于 adw-gtk3-dark 的圆角 Dracula 皮肤； Qt6 保留现有 Kvantum Material Dracula。只改必要配置项，个人字体、字号、视图和其他设置保留。 GTK 选择同步 settings.ini、Wayland 的 GSettings 与现有 XSettings 主题键；图标同理同步。 已分别用实际 GTK Wayland／X11 后端确认 Material Dracula，字体保持各自原值。 Kvantum SVG 主题与 Qt 调色板是两层，选 Kvantum 时以其主题为主；Qt5 不在本次控制范围内。 GTK4/libadwaita、自绘应用及沙箱应用各有主题机制，不强制注入 CSS。 已打开的应用需自行退出重开；刷新 Clavis 不关闭你的应用，Thunar 后台实例也可能需要自行退出再开。 新外观修改留存于 ~/.local/state/clavis/appearance-backups/；原主题资源不改。

9. 保存个人定制

  1. 修改 ~/.config/niri-clavis/local.kdl，而非原 ~/.config/niri/config.kdl。
  2. 验证 niri validate -c ~/.config/niri-clavis/config.kdl；成功后 niri 监控配置自动重载。
  3. Clavis UI 设置保存于 ~/.config/niri-clavis/settings/，不进入 Git。
  4. 要把通用改动收回 dotfiles，手动比较并选择性合并到 wm/clavis/.config/niri-clavis/。 不要整目录同步个人数据；这是为了避免提交隐私和下次部署覆盖。
  5. 改 QML 源码按源码 AGENTS 先格式化、再 scoped check；C++／翻译改动需重新构建。

迁移备份位于 ~/.local/state/clavis/wm-migration-*/ 和 profile-backup-*/。 迁移前 build 留作回滚记录，包含旧绝对路径；要恢复源码路径应重新构建，而不是复用旧 CMakeCache。

10. 排障和回退

  • 配置只读：test ! -L ~/.config/niri-clavis，并查看 helper 的 diagnostics.writable；不要绕过安全检查或 chmod 777。
  • 栏不见：用 Super+Ctrl+B 开“显示栏”；检查栏的模块区是否被清空；查看 Shell 服务状态。
  • 搜索误触：单独 Super 绑定已移除；若个人 local.kdl 又绑定了它，请自行移除那条覆盖。
  • 网络有设备无界面：使用 nm-applet / nmtui；不要重启 NetworkManager 影响当前连接。
  • 通知／托盘失灵：Super+Shift+B 恢复托盘；若仅 UI 异常，优先 Super+Alt+B。
  • Qt 更新后导入失败：重新 deps、build，再刷新 Shell。

回到原桌面：仓库根目录执行 ./scripts/setup-clavis.sh uninstall，保存工作，正常注销再选 Niri。 卸载移除本安装链接和 niri drop-in，保留运行配置、所有个人设置、源码和依赖；不重启当前 niri。 更多日志路径和细节见 USAGE、CONFIGURATION。

登录动画与蓝牙

正常 Niri 登录时，先显示用户名书写动画，再加载完整 Clavis；面板真实就绪后淡出。 这是独立的短生命周期 clavis-startup.service，不是新的登录 session；普通面板刷新不会重新播放。 首次画面或主面板失败时均有超时回退，不用虚假百分比表示加载。 更改显示名字可给该用户 unit 添加 Environment=CLAVIS_STARTUP_NAME=你的名字，字体与颜色入口是源码 Modules/Startup/StartupCover.qml。停用可屏蔽该用户 unit；登录继续正常进行。

蓝牙若显示 rfkill 阻止，现在仍可点击开启：仅在你请求开启时解除蓝牙软锁，再启用适配器。 不会在每次登录时强行打开蓝牙，不影响 Wi-Fi，也不绕过硬件开关。

视频壁纸边缘绿线

已确认本机 Waywallen 0.3.3 的 Vulkan 解码路径会在屏幕最右四列产生绿线。 当前通过 Waywallen 的视频设置将硬件解码改为 none（软件兼容模式），保留原视频、分辨率、帧率及各屏选择。 代价是 CPU 开销可能增加；以后驱动或渲染器修复后可在 Waywallen 设置里改回 auto。

双屏扩展排列

两个显示器的输出定义现由可编辑片段管理，不再因位于 personal-base 而只读。 设置 → 常规 → 显示器 → 配置 可拖动矩形，调整左右／上下位置，再通过预览保留。 当前外接在左、内置在右的实际布局及刷新率未被改变。迁移、备份与旧机器更新见 显示器只读与扩展排列。

音量滚轮、Emoji 与锁屏输入（2026-10-22）

  • 音量：拱石音量浮层、设备和应用音量滑块支持滚轮。向上增加、向下减少； 浮层每次调整 5%，Qt 滑块沿用其步长；浮层从静音开始调整会解除静音。 已验证真实滚轮事件改变数值；测试使用独立音频对象，没有改动当前音乐音量。

原生最小化时显示 Dock

启用 Dock 自动隐藏时，应用发出原生最小化请求，会让其所在屏幕的 Dock 显示约 2.5 秒。 鼠标移入可继续点击恢复，离开后仍沿用原有隐藏延迟；关闭自动隐藏时 Dock 本来就显示。 不改变焦点、不移动到隐藏工作区。按你后续澄清，最小化窗口保留在 Dock，点击 Dock 恢复；已清空此前两项自动折叠选择。 不需要先点 Dock 才能最小化。应用没有最小化按钮时才使用 Dock 的最小化入口。

可选：指定程序最小化后折叠（当前关闭）

入口：设置 → 常规 → 程序坞 → 折叠最小化程序。也可搜索“折叠最小化程序”直达。

  1. 先打开目标程序，再打开对应开关；选过的程序退出后仍留在设置列表，可随时关闭策略。
  2. 正常最小化后，窗口进入状态栏或拱心石的托盘折叠弹层，点击箭头可看到窗口标题；点击标题恢复该窗口。
  3. 同一程序多个窗口分开列出。只有最小化的窗口被折叠，其余仍在 Dock；未选择的程序维持原行为。
  4. 当选中程序的所有窗口都最小化，Dock 暂时隐藏该程序的槽位；不会删除固定项，恢复窗口或关闭全部窗口后固定入口重新出现。
  5. 关闭状态栏／移除托盘组件／该输出消失后，只要没有任何可见托盘，所有窗口自动回到 Dock，避免丢失恢复入口。
  6. 程序没有系统托盘图标也能用，只需提供稳定 app-id；无法识别身份的 unknown 窗口不提供持久化选择。
  7. 选择项保存在现有 settings/dock.json 的可选 foldMinimizedApps 字段，最多 128 个；旧配置无需手动迁移，默认不折叠任何程序。

这是真实 niri-edge 最小化窗口的恢复列表，不是移动到 scratch 工作区、不结束或暂停程序， 也不伪造应用自身的托盘菜单。原有“托盘图标常驻／折叠”选择继续独立生效。 这是额外可选功能，按你澄清的需求已关闭自动折叠；不删除 Dock 固定项。
